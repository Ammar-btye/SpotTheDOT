## High

**H1. The circuit-breaker cooldown is shorter than the call timeouts, so a hung dependency stalls the live replay over and over.**
- **Where:** `backend/app/services/http.py:27-36`, `backend/app/services/system1.py:42-50`, `backend/app/services/replay.py:104-113`, `docker-compose.yml:146-151`.
- **Evidence:**
  - The breaker opens for `BREAKER_COOLDOWN_S` (10 s) after one failure.
  - After the cooldown, the next real call is the probe, and it waits the full timeout.
  - Compose sets `SYSTEM1_TIMEOUT_S=30`, `MCP_TIMEOUT_S=60` and `EMBED_TIMEOUT_S=20`.
  - The replay awaits each event serially.
- **Impact:**
  - If System 1 accepts connections but hangs (for example, the SSH tunnel in hybrid mode), the replay stalls about 30 s, runs about 10 s of rules-only events, then stalls 30 s again.
  - `backend/README.md:107` says "costs one timeout, not one per event". That is false: it costs one timeout per cooldown window.
- **Fix:**
  - Probe with a 2 s `GET /health` (half-open) instead of a real call.
  - Use exponential cooldown (10, 30, 60 s).
  - Give replay calls their own short deadline: `asyncio.wait_for(..., 8)`.

**H2. On CPU, one dashboard forecast request blocks Laya for every replay event.**
- **Where:** `backend/app/routers/system1.py:93-109`, `amd/system1/service/engine.py:63,137-138`.
- **Evidence:**
  - `GET /system1/forecast?mission_id=` calls Laya live, in one request, for every action that has no stored prediction (for example 10 actions × 3 questions).
  - `/system1/predict` accepts up to 64 items.
  - The engine holds a single lock.
  - At the given CPU rate (about 8 s per 3 events, about 0.8 s per question pair), a 10-action forecast holds the lock for about 24 s. A 64-item predict holds it for minutes.
  - Requests the backend abandons on timeout keep running in the threadpool.
- **Impact:** Replay events queue behind the lock, time out, and trip H1's breaker. The live demo turns rules-only.
- **Fix:**
  - Pre-compute forecasts before the demo, and default `live=false` in the UI.
  - Cap live forecast items (≤5).
  - Have system1 return 429 when busy instead of queueing.

**H3. Destructive and ingest endpoints are unauthenticated, and CORS allows every origin.**
- **Where:** `backend/app/routers/ops.py:43-57`, `backend/app/routers/replay.py:20-25`, `backend/app/routers/events.py:15-27`, `backend/app/main.py:72-73`, `backend/app/config.py:63`.
- **Evidence:** `reset-demo` only requires `{"confirm": true}`. `replay/start {"reset":true}` also wipes data. `POST /events` accepts arbitrary events. `allow_origins=["*"]`.
- **Impact:**
  - Any web page open in the presenter's browser can wipe the demo or inject fake flags through localhost.
  - With `BIND_ADDR=0.0.0.0`, or if the backend is exposed for a hosted frontend, anyone on the venue Wi-Fi can do the same.
- **Fix:**
  - Require an `ADMIN_TOKEN` header on `/ops/*`, `/replay/*` and `POST /events*`.
  - Set `CORS_ORIGINS` to the frontend origin only.

## Medium

**M1. `combine()` emits inconsistent flags.**
- **Where:** `backend/app/services/validator.py:157-166`.
- **Evidence (probed):**
  - Parallel mode, Laya escalate+P4 with rules P4 → `escalated=True, P4, LOW`.
  - Parallel mode, Laya log+P1 with rules P3 → not escalated, `P1/CRITICAL`.
  - Serial mode, Laya log+P1 with rules escalate P2 → not escalated, P1.
  - The "escalated ⇒ P1/P2" guard exists only in serial mode (`:160`).
- **Impact:** Escalated LOW flags appear in the operator queue, and routine events are labelled CRITICAL.
- **Fix:**
  - Clamp escalated flags to at least P2, and cap non-escalated ones at P3.
  - Add the parallel-mode cases to `tests/test_validator.py`.

**M2. System 1 calls are logged twice in `app.model_calls`.**
- **Where:** `backend/app/services/system1.py:63-67`, `amd/system1/service/app.py:126-132`, `docker-compose.yml:94`.
- **Evidence:**
  - The backend and the service both insert a `system1` row with the same model, endpoint and device.
  - Compose enables service-side logging by default.
  - `/ops/model-calls` groups by system, model, endpoint and device (`backend/app/db/queries.py:589-601`), as does `app.get_model_call_stats`.
- **Impact:** The AMD latency evidence double-counts calls and mixes round-trip latency with server latency.
- **Fix:** Log the backend rows with `endpoint='/v1/predict (round-trip)'` (or group by `metadata->>'caller'`), or disable one of the two.

**M3. Pool exhaustion is treated as "database down".**
- **Where:** `backend/app/db/pool.py:72-74`, `backend/app/config.py:62`, `backend/app/services/calllog.py:36-43`, `backend/app/services/ingest.py:57-70`.
- **Evidence:**
  - `PoolTimeout` (3 s to acquire a connection) trips a 5 s fail-fast on every query.
  - Unbounded fire-and-forget log tasks share the same 10-connection pool.
- **Impact:** A slow Neon (cold start or venue Wi-Fi) or a polling burst makes replayed events silently `persisted:false`. They never appear in `events` or `flags`.
- **Fix:**
  - Trip only on connect errors.
  - Give logs a separate small pool or a bounded queue.
  - Set `DB_CONNECT_TIMEOUT_S` to 8 for Neon.

**M4. `/flags/{id}/context` and `/explain` have no overall deadline.**
- **Where:** `backend/app/services/mcp.py:62`, `backend/app/services/flags.py:186-192`, `amd/mcp/spot_mcp/embed.py:53-58`.
- **Evidence:**
  - `MCP_TIMEOUT_S` applies to each of 3 sequential JSON-RPC posts, then System 2 adds up to 60 s.
  - In compose, MCP_TIMEOUT_S is 60 s, so the worst case is about 240 s.
  - The MCP embedder has no breaker, so every packet waits `EMBED_TIMEOUT_S` (20 s in compose) when the embedder hangs.
- **Impact:** A hung dependency can leave the dashboard spinning for minutes.
- **Fix:**
  - Wrap the whole context call in `asyncio.wait_for` with about 20 s, and the whole explain with about 75 s.
  - Add a breaker to the MCP `HttpEmbedder`.

**M5. `db/setup.py seed` overwrites live flags and refills the demo.**
- **Where:** `db/setup.py:178-207,251-255`, `docker-compose.yml:59-63`.
- **Evidence:**
  - `seed_flags` runs `ON CONFLICT (triage_event_id) DO UPDATE` with reasons, score and `escalated=true`.
  - `seed_events` re-inserts all 500 replay events.
  - db-init runs seed on every `up`. The local DB currently holds 58 seeded flags and 500 events.
- **Impact:**
  - A mid-demo `make up` repopulates the queue and the feed.
  - Live flags lose their `laya_verdict`/`rules_verdict` reasons.
- **Fix:** In compose, run `seed --no-events` and make flag seeding opt-in (or `DO NOTHING` on conflict).

**M6. Contract drift: the MCP server treats the backend's verdict pseudo-rules as policy rules.**
- **Where:** `amd/mcp/spot_mcp/service.py:547,553,565,571,407`.
- **Evidence:**
  - The backend contract says `flags.reasons` starts with `laya_verdict`/`laya_unavailable` and `rules_verdict`.
  - The MCP server looks up `policy:laya_verdict` and `policy:rules_verdict` (2 of its 4 exact-policy slots are wasted).
  - It embeds "triage rule: laya_verdict rules_verdict …" as the policy query.
  - It truncates `reasons[:5]`, so only 3 fired rules reach System 2.
- **Fix:** Filter out the verdict pseudo-rules in the policy lookup and the query, and show the verdicts separately.

**M7. The MCP `.env.example` breaks the documented `docker run`.**
- **Where:** `amd/mcp/.env.example:21` (`MCP_HOST=127.0.0.1`), `amd/mcp/README.md:78,101`.
- **Evidence:**
  - `--env-file` overrides the image's `MCP_HOST=0.0.0.0`, so the server binds container loopback and the published port is dead.
  - Verified: with host=127.0.0.1, a request with `Host: mcp:8090` gets **421** from the SDK's DNS-rebinding check. With 0.0.0.0 it gets 200.
  - Compose is unaffected (`docker-compose.yml:119`).
- **Fix:** Remove `MCP_HOST` from `.env.example`, or add `-e MCP_HOST=0.0.0.0` to the README commands.

**M8. Builds are not reproducible.**
- **Where:** `amd/embed/Dockerfile:35`, `amd/embed/requirements.txt`, `amd/mcp/Dockerfile:7`, `db/requirements.txt`, `amd/system1/service/requirements.txt` (fastapi/uvicorn ranges).
- **Evidence:**
  - The embed image's CPU torch is unpinned. It resolved to 2.14.1+cpu, while system1 pins 2.12.0.
  - `mcp>=2.3,<3` is a young SDK. The server imports `mcp.server.mcpserver` and `mcp_types`, which a minor release could move.
- **Fix:** Pin the resolved versions: torch 2.14.1+cpu, transformers 5.19.0, sentence-transformers 6.1.0, fastapi 0.143.0, mcp 2.3.0.

**M9. `store_predictions` costs about 2N+2 round trips per event.**
- **Where:** `backend/app/db/queries.py:95-113`.
- **Evidence:** One DELETE plus one INSERT per question. About 13 DB round trips per action event in total.
- **Impact:** On Neon with 50-100 ms RTT, ingest is about 1 s per event even with GPU Laya. This is what bounds a fast replay once Laya is fast.
- **Fix:** One DELETE plus one multi-row INSERT, or a `UNIQUE NULLS NOT DISTINCT` index with `ON CONFLICT`.

**M10. Template explanations are cached as final.**
- **Where:** `backend/app/services/flags.py:182-201`, `backend/app/db/queries.py:251`, `amd/embed/ingest.py:279`.
- **Evidence:**
  - The fallback is stored with `state='DONE'`, so later `/explain` calls return the template even after System 2 is back, unless `refresh=true`.
  - `ingest.py` then indexes the templates as `explanation` docs ("earlier System 2 explanations").
- **Fix:**
  - Store fallbacks as `state='TEMPLATE'`, or skip the cache when `model='template'`.
  - Exclude `model='template'` in `build_explanations`.

**M11. Flag scores drift between seeded and live flags (rule drift, scoring).**
- **Where:** `db/policy_rules.py:19,225` vs `backend/app/services/validator.py:19,182-183`.
- **Evidence:**

| | db/policy_rules.py | backend validator.py |
|---|---|---|
| Base score P3 | 40 | 45 |
| Base score P4 | 10 | 20 |
| Increment | +3 per extra rule | +9·p_escalate |

  - `tests/test_policy_consistency.py` checks thresholds, verdicts and severity, but not scores.
- **Impact:** The queue ("open first, by score") mixes two scales whenever seeded and live flags coexist.
- **Fix:** Use one shared `score()` and extend the drift test to cover it.

## Resolved during the audit

**R1. `raw.spot_event_log.request_id` was in the contract but no migration created it.**
- **Where:** `docs/system2-rag-contract.md:148`. `db/migrations/005_raw_and_app_logs.sql:8-17` has no such column.
- **Evidence:** Absent in the local DB at audit time. The backend writes the column only if it exists (`backend/app/db/queries.py:70`), so it silently wrote nothing.
- **Fix:** The integrator added `db/migrations/008_spot_event_log_request_id.sql`, which runs `ADD COLUMN IF NOT EXISTS` plus an index, with target `logs`.
- **Audit of the fix:** Correct and idempotent. It sorts after 007, and 007's table-level grants cover the new column. Existing DBs need `db/setup.py migrate` re-run, and the backend's column cache picks the change up within 60 s.

**Resolved after the audit (fixer, 2026-10-10; details and tests in `docs/integration-log-2026-10-10.md` "Audit fixes").**
- **H3 resolved.** `X-Admin-Token` (`ADMIN_TOKEN`) required on `/ops/*`, `/replay/*`, `POST /events` and `/events/batch`; unset token → 503, wrong/missing → 401; CORS limited to `CORS_ORIGINS` (default `http://localhost:3000`). Tests: `backend/tests/test_auth.py`, e2e A0.
- **M1 resolved.** `combine()` clamps in both modes: escalated ⇒ P1/P2, not escalated ⇒ P3/P4, severity follows. The three probed cases and parallel-mode cases are in `backend/tests/test_validator.py`.
- **M4 resolved (backend side).** `REQUEST_DEADLINE_S` (45 s) bounds `/flags/{id}/context` and `/explain`, including every downstream call; past it they return the SQL packet / template with `fallback_reason: "deadline: ..."`, or 504 if the flag row can't be read. The MCP `HttpEmbedder` breaker is not done.
- **M5 resolved.** `db/setup.py seed` is insert-if-missing, and it loads the demo baseline only on a database's first seed; `--force-reseed` is the destructive path, and db-init never uses it. Test: `tests/test_seed_nondestructive.py`.
- **M7 resolved.** `MCP_HOST` removed from `amd/mcp/.env.example`; the documented `docker run --env-file` now serves on the published port (verified 200).
- **M10 resolved.** Templates are stored as `state='TEMPLATE'` and retried when System 2 is configured; `amd/embed/ingest.py` excludes `model='template'`. Tests: `backend/tests/test_fallbacks.py`, e2e A3.

## Verified OK

- **Rule drift (thresholds and logic):**
  - The vendored MCP `policy.py` and `questions.py` are byte-identical to the canonical copies (`diff` rc=0).
  - `db/policy_rules.py` and `backend/app/services/validator.py` restate exactly the `label_action`/`label_mission` predicates, with every threshold taken from `policy.py`: P1 = sev4, sev3∧crit≥3, failed∧batt≤15, comms∧batt≤25; P2 and P3 likewise; missions too.
  - The integrator's drift test passes on all 297 events.
  - The only differences are scores (M11), detail wording (`failed_on_critical_asset`, `battery_low`, `action_failed`, `mission_reported_failed`) and L2.
- **Search SQL** (local pg17, pgvector 0.8.7):
  - Similarity equals 1 − cosine distance (self-similarity is 1.0).
  - NULL filters mean "no filter", the kinds filter works, and `min_similarity` works.
  - A NULL embedding falls back to lexical-only search.
  - Empty, stop-word-only and punctuation-heavy queries don't error.
  - `text_match` is true on 17 of 50 rows for "HX-204", with 0 false positives.
  - RRF is Σ1/(k+rank) over a FULL OUTER JOIN.
  - `proconfig` carries `hnsw.iterative_scan=strict_order`.
  - Exact search takes about 17 ms over 493 docs.
- **Hybrid contract change:** both callers (MCP and backend) use the new `similarity` and `text_match` columns.
- **Flags columns:** `triage_event_id` (unique index; `ON CONFLICT` infers it), `priority` and `category` are used by the seed, the backend, the MCP and ingest.
- **Backend → System 1 compatibility:** all 477 triaged replay events built by `Reference.canonical` pass system1's `parse_jobs`. Their `render_json` output is byte-identical to the kit-built training events.
- **Backend → MCP interop:** the real streamable-HTTP server (mcp 2.3.0, stateless, JSON responses) accepts the backend's `2025-06-18` handshake. `get_flag_context` returns the packet, and `_meta.request_id` is honoured.
- **MCP security:**
  - Every query runs in a READ ONLY transaction (`CREATE TEMP TABLE` is rejected) with a 5 s `statement_timeout` (`pg_sleep(6)` is cancelled).
  - Compose connects as a `spot_mcp_reader` member.
- **SQL injection:** every string-built SQL statement interpolates only constants or whitelists (`DIMENSIONS`, column tuples); values are always bound. MCP inputs are regex- or enum-validated, and the tests include injection strings.
- **Idempotency:**
  - `raw` has `UNIQUE (source, sha256)`, and `raw_sha256` matches the seed's line hashes.
  - `events`, `flags` and `documents` are upserts. Flag status survives a re-ingest.
  - Predictions use `IS NOT DISTINCT FROM`, which handles mission NULLs (0 duplicates).
  - Document change detection: Python md5 equals SQL md5.
- **TRIAGE_MODE:** serial requires both verdicts to escalate. In parallel, `more_urgent` lets Laya raise the priority but never lower it below the rules' floor, so a Laya miss on a critical asset is caught (tested).
- **Calibration:** the service calls `predict(calibrated=True)` with per-(qtype, k) temperatures, and parity with `LayaRunner` passes. The temperature test is tautological, though: it re-derives T from `_temp`.
- **Containers:**
  - All five images run as non-root (inspected).
  - Both GPU images install torch first and fail the build if a later pip step replaces it.
  - The system1 and embed HEALTHCHECKs test readiness (`model_loaded` / 503 while loading).
  - Allowlist `.dockerignore`s are correct. No `.env` file is present in any image.
  - The root `.env` is gitignored. A secret regex scan of the tree found nothing.
- **Image bloat:** 818 MB of embed's size is torch and 498 MB is transformers plus sentence-transformers. There is no avoidable bloat beyond these.
- **Contract basics:** ports and env var names match the contracts.
- **Pool recovery:** `psycopg_pool` regrows the pool on demand after an outage (`reconnect_timeout=0`).
